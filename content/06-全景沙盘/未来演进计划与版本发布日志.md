# **一、 系统架构与演进总则**

本计划文档用于沉淀乐团世界全景交互沙盘（Tokyo Sandbox）与数字花园维基站的后续技术升级规划。所有演进方向均严格遵循以下三项不可违背的底层准则：

1. **真实世界线与自然呼吸感**: 拒绝舞台剧式的真空生活，深度融入真实的东京都市脉络、学园作息、现实节假日节奏与复杂社会百态。  
2. **反脸谱化与深层心理还原**: 坚决杜绝把角色矮化为单一二创符号或梗标签，持续探索角色在现实重负与音乐追求交织下的立体人性。  
3. **安全物理隔离与纯洁度保证**: 严禁将三次元隐私带入世界观，公开发布区与私人母本区永久保持单向物理隔离。  
4. **五小时跨度回溯与最终状态锚定机制 (5-Hour Window Retrospective)**: 后台定时守护进程每 5 小时被唤醒时，记录的事件绝不拘泥于任务触发当下的单一时间点截面。在过去的 5 个小时内发生的生活琐事、人际互动、突击小测或排练波折均可作为推演素材；但事件叙述完毕后，必须将全员的物理与心境状态准确锚定在当前窗口结束时刻的最终状态（如深夜安歇、清晨通学、放学集结）。  
5. **凌晨低频偶发随机事件协议 (Low-Frequency Midnight Event Protocol)**: 在东京时间凌晨时段（00:00 至 06:00 JST），全员以在各自居所卧室深度安睡为主基调；系统仅以极低概率（偶发、低频，绝不频繁）随机触发一次真实静谧的深夜微小切片（如骤起夜雨起身关窗、渴醒去厨房喝水、祥子桌前偶发记下四小节配器动机、灯夜灯下重新整理小石头、立希听几分钟排练分轨后重新睡下、降温裹紧被角）。事件记录必须保持极致克制，在轻微涟漪后自然重归深睡。  
6. **双轨更新与协同隔离规范 (Dual-Track Workflow & Isolation)**:  
   1. **轨道 1（日常内容零接触全自动流）**: 主世界编年史、乐团共享日记、成员长期记忆档案、世界书等 16 篇 Markdown 文档，直接在 Google Docs / Google Drive 中更新。通过 GitHub Actions 定时轮询与 dispatch 信号全自动抓取、编译并发布上线。创作者与本地无需介入。  
   2. **轨道 2（核心架构与前端代码手动推送流）**: 沙盘 HTML/JS 逻辑、音频及大型二进制资产由云端单文件交付，zcode 在本地环境负责语法断言、补丁合并与 `git push`。创作者彻底免除手动 Git 命令行操作；生产仓库的推送权由 zcode 本地独占，云端保持零凭据、纯交付准则。  
7. **沙盘样式与代码交付契约 (Sandbox CSS & Delivery Baseline)**:  
   1. **媒体查询尾部锁定**: 沙盘源码中的竖屏（≤768px）与横屏（≤920px landscape）媒体查询样式块，永久置于 `<style>` 最末尾，且严格以仓库侧 zcode 实测基线为准，云端不得重写或挪动。  
   2. **界面与音频规范**: 日记按钮固定于左下角（`.sandbox-diary-wrap`，`bottom: 20px; left: 20px`）；音频优先沿用 `./audio/yidong_vocals.wav` 相对路径；语音触发统一调用 `SAKIKO_AUDIO_SYSTEM.play(triggerType, extraInfo)`。  
   3. **交付语法红线**: 所有交付前端代码必须在本地预先通过 Node.js（`node --check`）100% 语法零报错断言，严禁孤儿语法片段上云。  
8. **公开发布区隐私红线公约 (Public Release Privacy Red-Line Convention)**:  
   1. **记忆档案彻底脱敏**: 11 份成员专属记忆文档中，彻底删除「用户专属交互沉淀日志」、「用户关系档案」与「用户关系画像 (User Dossier)」章节，相关内容封存入私人母本区；公开发布区仅保留原作情景记忆、世界观内设定与调用协议。  
   2. **外部私密直链禁令**: 公开发布区严禁出现指向私人母本文件夹（如剧本库、母本库）的外部 Google Drive 直链。  
   3. **图谱幽灵节点防范**: 文档公约与规范示例中，严禁直接书写字面的双方括号占位符，由同步管道进行定点中性化防御。  
   4. **随想笔记隔离**: 《创作者世界观随想笔记》正文随笔隐蔽至母本区，公开发布区仅保留公约规范框架。

# **二、 核心功能演进路线图 (Feature Roadmap)**

## **方向 1 · 全员二十四小时时空漫游与现实假期引擎 (24-Hour Spatial Routine & Holiday Engine)**

* **现实日历与日本法定假期联动**:  
  引入日本节假日（祝日）与学园校历状态判断机制。系统将自动识别工作日（平日）、周末（土日）、黄金周（GW）、盂兰盆节、春假、暑假与寒假：  
  * **平日（授课日）**: 08:30\~15:30 角色自动收拢于羽丘、月之森与花咲川三大核心学园校舍；  
  * **周末与法定节假日**: 角色不再处于学园，而是分散至池袋商圈、涉谷乐器行、若叶家温室花园、琴房自主加练、或是兼职打工；  
  * **长假（如暑假/寒假）**: 触发合宿推演、巡回试音、密集商业通告或个人独处旅行等大跨度日常。  
* **二十四小时昼夜轨迹漫游**:  
  建立全员 11 人的时段坐标迁移矩阵，访客在一天中不同时段打开沙盘，会在地图不同据点偶遇正在通勤、排练、上课或休息的成员。

## **方向 2 · 丰川祥子个人生计与音乐发展路径的多元拓展 (Beyond Call Center)**

* **生计结构的多元化转型**:  
  呼叫中心夜班是现实困境中迫不得已的起点，但绝非人生的终点站。随着剧情因果演进与人际网络展开，祥子的生计将逐步向更贴合其深厚音乐素养的方向拓宽：  
  * **古典钢琴家庭教师与陪练**: 承接月之森或目黑一带学龄琴童的高阶古典钢琴家教，换取更加稳定且体面的报酬；  
  * **商业乐曲配器与编曲代工 (Arrangement Commissions)**: 借助初华或海铃的地下人脉，匿名承接商业广告、短视频配乐及其他独立乐队的弦乐配器订单；  
  * **专业扒谱与管弦总谱制作**: 为专业录音棚制作高精度的总谱与各声部分谱；  
  * **Ave Mujica 商业版税与演出分账**: 随着假面乐队由地下录音走向正式商业化舞台，逐步以完全自立的音乐人身份走出底层泥潭。

## **方向 3 · 东京气象实时映射与动态降水光影 (Tokyo Realtime Weather)**

* **气象 API 实时接入**:  
  动态调用东京都丰岛区实时天气数据，驱动 Canvas 渲染层的环境滤镜（晴天落日暖光、阴天冷灰暮色、夜雨反光霓虹）；  
* **动态降水与雨景声画**:  
  东京降雨时，神田川水面泛起涟漪，角色立绘自发切换为撑伞或避雨动作，并伴随编年史与日记中的下雨因果回响。

## **方向 4 · 据点微型空间声景与程序化白噪音 (Spatial Soundscapes)**

* **纯原生 Web Audio 声景**:  
  基于浏览器原生合成器，轻量生成各据点的沉浸式环境音：  
  * **神田川岸**: 流水与晚风白噪音；  
  * **RiNG**: 地下室排练室电流底噪与轻微鼓点；  
  * **客服中心**: 静谧键盘敲击与微弱机房低频；  
  * **月之森林荫**: 微风掠过树梢的细碎声响。

## **方向 5 · 少女们的私密生活道具柜 (Relic Cabinets)**

* **可交互的便签与遗物展示栏**:  
  为每位角色打造个性化展示空间：  
  * 高松灯的石头与创口贴标本盒；  
  * 长崎素世的茶叶手账与修琴工具箱；  
  * 椎名立希的吧台黑板手写单；  
  * 丰川祥子的匿名手稿乐谱夹。

# **协同规范**

* **双轨制**：轨道 1——16 篇文档在云端编辑，30 分钟轮询 \+ dispatch 自动上线，无人工环节；轨道 2——沙盘 HTML/音频等代码资产以 Drive 单文件 \+ 清单交付，zcode 本地审计（语法断言/隐私扫描/补丁合并/浏览器实测）后发版。  
* **沙盘交付六项自检**：① 修改基础必须先下载线上实时版 static/sandbox/，严禁用旧包或缓存；② 内联脚本全部通过 node \--check；③ 浏览器实际打开验证渲染一帧无异常；④ candidateUrls 有且只有 \['./audio/yidong\_vocals.wav'\]；⑤ 竖屏/横屏两段媒体查询块原样保留在样式表末尾、日记按钮 sandbox-diary-wrap 且 left:24px、语音方法名为 play；⑥ 无痕与直链自测公开可达性：交付前必须通过无痕窗口或公开直链测试可达性，确认返回 200 状态码、具有「知道链接的任何人可查看 (reader: anyone)」权限且内容包含当前版本的版本号标记（如 v2.5.0），杜绝 401 登录墙拦截。  
* **运行节奏与补仓机制**：每日东京时间 09:00 JST 自动执行时空巡检。当未来切片余量低于 48 小时（或队列为空）时，自动触发未来 5 天（约 120 小时）的滚动预推演；单次补仓可覆盖未来 5 天脉络，在保持每日 09:00 JST 48 小时警戒线巡检的前提下，大推演触发间隔延长至 3\~4 天，有效降低生成调用频次并保持各侧零改动。平时仅作状态同步与已解锁星轨播报。切片标头严格采用 \#\#\# 【YYYY-MM-DD HH:mm JST | 标题】；正文支持附带 \* 气象: 叙事元数据。创作者发出“归档”指令后，切片一次性写入当月编年史卷（日记写入共享日记本），同次归档确认《编年史卷索引.md》包含当月卷，跨月时自动在索引追加新卷 ID。  
* **气象三层解耦规范**：切片中的 \* 气象: 字段为世界观内叙事与戏剧氛围元数据，后台定时任务严格依循《东京气候速查表》按月份进行纯内生时令推演，严禁任何外部网络请求与代码调用；与沙盘前端 Open-Meteo 实时气象物理层完全解耦（叙事层与氛围层分离）。  
* **内容红线与幽灵节点防御**：在所有规范条目、格式示例或提示文字中，格式示例一律使用全角括号［［...］］书写（如 ［［角色名\_长期记忆档案|角色名］］），严禁在任何同步范围文档的示例说明中出现字面半角双方括号，杜绝被 Quartz 解析为虚假双链与幽灵节点；实际生成故事切片时则正常使用半角双括号 [[角色名_长期记忆档案|角色名]]。用户相关交互记录与三次元隐私永不进入公开发布区。  
* **记忆档案规则**：记忆档案权威源为 Git 仓库（demux 独占写入），云端 11 份记忆 Docs 已封存勿动；编年史切片中的分流指引正常写 [[角色名_长期记忆档案|角色名]]: 描述（多目标用 [[A_长期记忆档案|A]] & [[B_长期记忆档案|B]]: 描述）。
